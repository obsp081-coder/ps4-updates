# PS4 Auto Updater v0.3 — PS4 Native Scanner (تجربة أولية)

> ⚠️ **ليست نسخة نهائية لتحديث الألعاب.** هذا نموذج Native للـPS4 يقرأ ملفات البيانات المحلية فقط في حال كانت متاحة له، ويكتب فهرس `inventory.json` على الجهاز. لا يحتوي على شاشة عربية بعد، ولا ميزة تنزيل/تثبيت ملفات PKG، ولم يُختبر على PS4 بنظام 14.00.

## لماذا هذه الخطوة؟

v0.2 اجتاز اختبارات Linux، لكنه لم يكن ملفًا يعمل على السوني. v0.3 يضيف **مصدرًا قابلًا لمحاولة البناء باستخدام OpenOrbis** وملف GitHub Actions مستقلًا للبناء. سنعرف من تجربة آمنة إن كان التطبيق يستطيع قراءة بيانات الألعاب في نظام المستخدم دون لمس قاعدة النظام أو تغيير GoldHEN.

## ما الذي يفعله البرنامج؟

- يحاول قراءة `param.sfo` من `/system_data/priv/appmeta/CUSAxxxxx/param.sfo`، بما فيها `external/`.
- يسجل اسم اللعبة، CUSA، إصدار اللعبة، وContent ID، إن كانت موجودة في ملف SFO.
- ينشئ `/data/PS4AutoUpdater/inventory.json` و`/data/PS4AutoUpdater/status.txt`.
- لا يكتب إلى `app.db`، ولا يعدل الألعاب، ولا ينزل تحديثات، ولا يتصل بالإنترنت.
- يسجل `metadata_only: true` و`installed_confirmed: false` **عن قصد**: وجود SFO وحده لا يثبت أن اللعبة مثبتة فعلًا. المرحلة التالية ستدمج ذلك مع قاعدة بيانات التطبيقات بوضع القراءة فقط بعد التحقق من الصلاحيات.

## التحقق على الكمبيوتر

يمكن تجربة الماسح على بيانات اصطناعية من دون السوني:

```sh
python3 tests/test_ps4_scanner.py -v
```

نجحت **7 اختبارات** محلية وقت تجهيز الحزمة. هذا لا يثبت توافق تطبيق PS4.

## إضافة الملفات إلى GitHub

1. فكّ الضغط وارفع مجلد `ps4-auto-updater-v0.3` إلى جذر المستودع `obsp081-coder/ps4-updates`، بجانب `ps4-auto-updater-v0.2`، دون حذف الملفات القديمة.
2. يحتاج GitHub Actions ملفات Workflow تحت **جذر** المستودع: `.github/workflows/`. لعمل ذلك، من GitHub اختر `Add file` ← `Create new file` واكتب اسم الملف بالضبط:

   `.github/workflows/ps4-build.yml`

3. الصق محتوى `ps4-auto-updater-v0.3/workflow/ps4-build.yml` في الملف الجديد واحفظه في `main`.
4. افتح **Actions** ← **PS4 Native Scanner Build (Experimental)** ← **Run workflow**.
5. إذا نجح تشغيل الـWorkflow، ستجد `ps4-scanner-experimental` في قسم **Artifacts**. يتضمن ملف PKG مبنيًا *إن نجح البناء*. لا تعتبر نجاح GitHub Actions دليلًا على النجاح على السوني.

هذا الـWorkflow منفصل عن اختبارات v0.2 القديمة، ولا يغيرها.

## اختبار الجهاز (بعد نجاح البناء والتأكد من الملف)

**لا تثبت الحزمة على جهازك الآن حتى نراجع أول نتيجة بناء من GitHub.** حين نصل للتجربة:

1. نتأكد من أن الحزمة خاصة بتطبيقنا التجريبي فقط، ولا تحتوي كود تحديثات أو تعديلات نظام.
2. نثبتها بطريقة GoldHEN المعتادة؛ قد تنهي التشغيل سريعًا لأن لا واجهة رسومية لها.
3. عبر FTP نتحقق من وجود `/data/PS4AutoUpdater/status.txt` و`inventory.json`.
4. إذا فشل الوصول للبيانات نتوقف ونراجع السجل؛ لا نعيد بناء قاعدة بيانات PS4، ولا نغيّر الترخيص أو إصدار النظام.

لا ترسل قاعدة بيانات النظام `app.db` كاملة، ولا ترفعها إلى GitHub. إذا احتجنا تشخيصًا، نشارك عدد الألعاب وأكواد أخطاء غير حساسة فقط.

## حدود المشروع
